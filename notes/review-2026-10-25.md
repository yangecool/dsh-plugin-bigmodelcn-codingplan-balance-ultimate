## P1 findings

### P1-1 — The Models-settings credential note now renders on every pi-ai provider card, not only coding-plan cards

- Where: `src/client/models-row.js:276-277` (`const gated = … config.providerIds; if (gated.length > 0 && !gated.includes(providerId)) return null;`), with the new default `lib/host/constants.js:101` (`providerIds: []`), note copy `src/client/models-row.js:279-300`, docs `README.md:36-39` (claims “a note inside each coding-plan provider card”).
- Evidence: `settings.models.provider-card` is keyed by the adapter settings namespace (`ui-settings-models/src/client/ModelsSection.tsx:451-453`, keyed with `row.entry.settingsNs`), so the plugin's `llm-pi-ai` key receives **every** card of the pi-ai adapter family, not only `zai-coding-cn`. With the final default `providerIds: []` the only gate is disabled. Smoke render of `ProviderCredentialNote` with `providerIds: []` and a signed-in snapshot produced the managed-credential copy for `zai-coding-cn`, `zai`, **`openai`, `anthropic`, and `github-copilot`** (all rendered the same “Model inference credential is provisioned automatically by the BigModel OAuth sign-inZAI_CODING_CN_API_KEY” text).
- Impact: users who add any other pi-ai provider (OpenAI, Anthropic, Copilot, OpenRouter, …) see a factually wrong claim that their API key is provisioned by BigModel OAuth, plus a “Sign in to BigModel” inline action on a card whose credential the plugin does not manage. This is a regression introduced by the last default change (the note previously piggy-backed on the `zai-coding-cn`/`bigmodel-coding-cn` default list).
- Fix: gate the note by the route's own identity instead of the composer-widget gate — e.g. `const CODING_PLAN_ROUTES = new Set(['zai-coding-cn', 'zai'])` and return `null` for others, or match `provider.defaultBaseURL` against `open.bigmodel.cn/api/coding` / the configured `inferenceCredentialRef`; keep `providerIds` for the composer widget only (a separate config key if users must configure the note). Update README/contracts wording accordingly. `bigmodel-coding-cn` is not a DSH pi-ai route at all, so the old default pair was also half dead.

### P1-2 — Inference credential can survive logout: `clear()` does not fence attempts that start after its generation bump (proven interleaving)

- Where: `lib/host/inference.js:151-160` (`stillOwnsAttempt`), `lib/host/inference.js:288-301` (`clear()`), `lib/host/snapshot.js:244-251` (`clearLoginState`) and `lib/host/snapshot.js:734-748` (`logout`), which call `inference.clear()` **before** `store.clearAuth()`.
- Evidence: `/tmp/inference-logout-race.mjs` (deterministic fake credentials + gated account):
  1. `clear()` bumps generation, reads the old auth document and awaits `credentials.unset`;
  2. a timer-driven `sync()` starts **during that await** — it captures the bumped generation and reads the still-present auth document;
  3. `clear()` finishes (writes `inference: null`, resolves); the logout flow has not yet deleted the auth document;
  4. the in-flight material resolves inside that window → `stillOwnsAttempt` sees the same generation, same `accessToken`/`family`, enabled config and unchanged ref → commits `credentials.set(...)` and writes bookkeeping;
  5. `store.clearAuth()` then runs; the credentials store keeps `ZAI_CODING_CN_API_KEY = PROJECT-TOKEN-FRESH` with no auth document recording it.
  The registered test suite covers only “attempt in flight **before** logout” (`tests/host/inference.test.mjs:516`) and “logout during the credential write” (`:548`); an attempt that starts after `clear()`'s bump is not covered.
- Impact: in a narrow but real interleaving (logout or inference-disable while the 60 s renewal tick / a forced overview refresh is in flight) the plugin-written project token remains in the credential store after logout. The auth file is deleted, so the plugin can never clean it up; the value also permanently shadows an ambient env fallback with no owner. This contradicts “logout unsets the credential the login wrote” (`README.md:138-142`).
- Fix: make logout atomic from the credential's point of view. Minimal ordering fix: capture `auth.inference`, delete the auth document first (`store.clearAuth()`) so any later `stillOwnsAttempt` reads `null`, then `credentials.unset(...)`, then drop caches — i.e. add a single `inference.releaseLogin()` used by `snapshot.clearLoginState`/`logout` that owns that order. Alternatively keep a `clearing` flag set before `generation += 1` and cleared only after the auth document is gone, make `performSync` refuse to start while `clearing`, and `await inFlight` in `clear()`. Add the interleaving (sync starts after the bump) to `tests/host/inference.test.mjs`.

### P1-3 — Uninstalling the plugin leaves the OAuth tokens and the provisioned inference credential behind; the documented uninstall path says nothing about it

- Where: `README.md:54-57` (“Uninstall: `dsh plugin --profile web remove …`”), `lib/index.js:46-62` (the plugin's only unload cleanup is the inference timer and the route table; nothing releases the credential or the auth file), `lib/host/store.js:164-207` (auth document is plugin-owned under `$DSH_HOME`).
- Evidence: the plugin has no uninstall hook in the DSH package model (a removed bundle's fiber is disposed, then the package directory is removed), and nothing in every observed install/remove path deletes `~/.dsh/bigmodelcn-codingplan-auth.json` or unsets the reference it wrote. Live state confirms both artifacts exist today: `bigmodelcn-codingplan-auth.json` (mode `600`, 1605 B with OAuth + ZCode tokens) and `.credentials.yaml` `refs.ZAI_CODING_CN_API_KEY`. The README's uninstall section only names the package command.
- Impact: a user following the README uninstall leaves a usable OAuth token file and a live project token in the Harness credential store; the project token keeps shadowing the reference's ambient fallback until it expires, and the OAuth token can be replayed against BigModel/ZCode endpoints. This is the “orphan on uninstall” hazard in the review scope.
- Fix (docs are the minimum actionable change because DSH has no uninstall callback): add an explicit uninstall runbook to README/CHANGELOG — “sign out in the page first (this unsets the credential and deletes the auth file); if you cannot, delete `$DSH_HOME/bigmodelcn-codingplan-auth.json` and remove the `ZAI_CODING_CN_API_KEY` reference (or run `dsh` and unset it in Settings → Models)”. Optionally add a best-effort `ctx.effect(() => () => { void inference.clear(); })` so reload/removal unsets the reference the login wrote (note: this runs on HMR reload too; the next start re-issues it from the auth document, so document that behavior).

## P2 findings (polish / low-probability)

1. **Release failure drops bookkeeping instead of retrying** — `lib/host/inference.js:102-109` (`unsetQuietly` swallows errors), `116-126` (`release`) and `288-301` (`clear`) write `inference: null` even when `credentials.unset` threw; test `tests/host/inference.test.mjs:490` documents this as intended. If the credential store is temporarily unwritable at logout, the only pointer to the orphan is dropped and no later cleanup can find it. Keep the bookkeeping (and the status error) on release failure so the next logout can retry.
2. **Inference timer disposal does not settle in-flight work** — `lib/host/index.js:46` + `lib/host/inference.js:329-341`: the disposer only clears the interval; an attempt started before unload can still `credentials.set(...)` after the plugin fiber is disposed (write after disposal; combined with P1-3). Track the in-flight promise and abort/skip commits once disposed.
3. **Oversized-body 413 is unreachable** — `lib/host/http.js:51-59`: on limit breach the code rejects and calls `request.destroy()`; the route handler's `sendError` then writes to a dead socket. Proof `/tmp/oversize-body-proof.mjs`: server alive, handler sees `413`, client gets `ECONNRESET` rather than a 413 JSON error. Reject without destroying (or `request.resume()` the remainder) so the documented status reaches the caller; add the case to `tests/host/integration.test.mjs`.
4. **Stale CHANGELOG after the final default change** — `CHANGELOG.md:62` still claims the widget “only appears for providers listed in `providerIds` (default `zai-coding-cn`, `bigmodel-coding-cn`)”; `CHANGELOG.md:50` says 237 tests while the suite is 239; `bigmodel-coding-cn` is not a DSH pi-ai route (`packages/llm/llm-pi-ai/src/provider-data.generated.ts` has only `zai`, `zai-coding-cn`). README already updated correctly.
5. **`family` setting has no visible effect while signed in** — the snapshot resolves the family from the stored auth first (`lib/host/snapshot.js:602`), while `/api/config` only writes `config.family`; the page's family selector (`src/client/page-settings.js:148-162`) therefore changes nothing until the next sign-in and the badge keeps the auth family. Label it “used for the next sign-in” or prompt a re-login when it changes.
6. **`cancelLogin()` does not cancel the Host flow** — `src/client/state.js:535-539` only stops client polling; there is no Host route to call `oauth.cancel()`, so the relay flow lives up to its 5-minute cap and a stale authorize URL stays valid. Harmless today (a new `start()` replaces the flow), but the visible “Cancel” is client-only; add a cancel route or say so in contracts.
7. **Popover first-open position jump** — `src/client/indicator.js:775` initialises position with `measurePosition(triggerRef.current)` during render, when the ref is not yet attached on the first open (React commits refs after child render), so the popover paints at the fallback placement (`:926-927`) for a frame and jumps when the `ResizeObserver` fires. Measure in `useLayoutEffect`/effect instead; also keeps the render pure.
8. **Models-row sign-in time ignores locale** — `src/client/models-row.js:200` calls `formatDateTime(auth.loggedInAt)` with the default `'en'`, so the zh UI shows an en-US formatted timestamp; pass `locale` from `useLocalized()`.
9. **Dead `include:llm-pi-ai` alias** — `src/client/entry.js:109-118` registers the keyed card entry twice. `settingsNs` is `ctx.fiber.entry?.options.id` (`packages/llm/llm-pi-ai/src/index.ts:156`), and the Loader prefixes an entry's **id getter** (`vendor/loader/src/config/entry.ts:66-72`) but never `options.id`; the shipped row id is `llm-pi-ai` (`packages/bundle/base/cordis.patch.yml:135`). So the plain key is the one dispatched and the `include:` alias is inert (a key no card dispatches silently never renders). Drop the alias/comment, or keep it only with a precise reason.
10. **Dead client helpers / dictionary surface** — `src/client/format.js:247-252` `WINDOW_KEY_CANDIDATES` lists `quota.window*`/`page.window*`/`widget.window*` keys that no dictionary ships (`windowLabel`, `formatLocaleId`, `durationMinutes` are also unused); `src/client/dicts-core.js` carries 38 keys nothing references (`action.*`, `state.*`, `auth.*`, `app.title/subtitle`, `time.tomorrow/resetIn/resetAt`) while the page/widget duplicate their own. Either wire the core vocabulary into components or trim it; drift here is how a missing-key raw string reaches the UI.
11. **`state.useReset` JSDoc contradicts the route contract** — `src/client/state.js:474` documents `'fiveHour' | 'week'`, while the Host route accepts only `FIVE_HOUR`/`WEEK` (`lib/host/routes.js:58-69`); callers correctly pass the wire enum (`src/client/page-sections.js:414-427`). Fix the JSDoc to prevent a future caller from copying the wrong values.
12. **Settings-section page scroll nesting** — `src/client/entry.js:87-93` reuses the full page (root `.bmc-page{height:100%;overflow-y:auto}`, `page-css.js:12-20`) as the `settings.section` body; inside the settings shell this can produce a nested scroll container / clipped page. Verify in the browser (the plain settings entry was not rendered live) or give the page a container-agnostic root.
